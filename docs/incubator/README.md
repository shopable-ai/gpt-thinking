# Incubator｜孵化中的想法、研究与商业模式

Status: Incubating
Updated: 2026-09-22

## 定位

这个目录用于暂存尚未形成稳定知识或正式决策的灵感、商业模式假设、研究提示词、技术候选、方案比较与受控实验。

“暂存”表示允许变化和后期整理，不表示自动删除或无须保留来源。这里的内容不应自动视为市场事实、已验证方案或已接受决策。

## 轻量存放方式

```text
聊天、灵感或外部线索
        ↓
docs/incubator/<topic>/
        ├─ README.md：为什么研究、核心思路、现状、下一步
        ├─ 研究提示词：需要实际继续执行时再保存
        └─ 证据、报告、实验：实际产生时再添加
        ↓
补证、验证、修订
        ↓
继续研究 / 暂停 / 放弃 / 迁入合适的知识库或执行项目
```

只有一句话的想法可先写一个主题 Markdown；材料增多后再变成主题目录。不要每个想法都强制创建整套文件。

不另建与此重复的 `tmp/`、`inbox/`、`ideas/` 总入口，也不预先搭建工作流引擎、复杂标签系统或层层分类。

## 与未来正式整理的关系

`docs/knowledge/`、`docs/decisions/` 只是可能的未来去向，不是本次已创建或必需的目录。

有稳定知识或真实决策后，再判断是否迁入这些目录、其他知识库或具体项目。迁移时保留来源、日期、结论变化和新入口；不要直接删除有价值的论证摘要。

## 使用规则

1. 每个主题说明状态、日期、核心问题和未验证事项，区分用户目标、历史讨论、研究证据和当前假设。
2. 重要核心思路放在主题总览，不能只留一个让人无法理解背景的长提示词。
3. 新一轮沿用当前主题文件；重复内容优先更新，不每轮新增一个“最终版”。历史变化由 Git 保存，重大转向在总览简述。
4. 价格、政策、产品功能、市场数据保留来源与日期；供应商宣传、公开报价、真实成交分开。
5. 不复制整段聊天或受限外部内容凑档案；保留可继续判断的必要信息。
6. 研究完成后，写回实际结果、证据缺口和下一步；没有完成的实验或成交不得标为已验证。
7. 写入前后检查目标分支与最新提交，尊重其他会话的变更，不重置或强推。
