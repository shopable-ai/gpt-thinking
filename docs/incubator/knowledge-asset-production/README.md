# 垂直知识内容与多元变现｜核心思路与研究入口

Status: Incubating / 商业假设待验证
Updated: 2026-09-22
来源：本轮用户明确的目标、讨论摘要与上传的新版研究提示词；不是本轮重新完成的市场研究。

## 1. 当前要研究什么

> 自己经营一个垂直知识业务：从视频、访谈、课程、文章、官方资料与实践中发现知识，整理成有独立价值的内容，吸引相关读者，再通过书籍、教学、工具、服务、软件推广、广告、会员或招聘等方式变现。

书和电子书可以直接卖，可以是核心产品，不必被限定为赠品或引流材料。也可以研究正规联盟推荐、授权分销和专家合作，并不要求所有商品自己制作。

这里先保存方向与问题，不预先宣布市场已经成立、已经盈利或应当选择某个领域。

## 2. 为什么更新方向

之前的讨论与旧提示词主要围绕：客户给出自己的视频，由我们制作文章、Guide / Playbook，再收取服务费。

用户随后明确：主要还要研究自己做内容、卖书、卖课及其他变现，而不是默认只承接内容外包。

因此当前区分三种模式：

| 模式 | 谁经营内容或产品 | 研究位置 |
|---|---|---|
| A. 客户内容资产化服务 | 为客户制作、编辑或维护知识资产 | 保留比较，不默认首选 |
| B. 自营垂直知识业务 | 自己经营受众、内容与相关产品或交易 | 当前优先研究的主线，不等于已验证最佳 |
| C. 与专家合作经营 | 与作者取得授权后联合制作、销售或分成 | 与 A、B 一并比较 |

“服务可能较容易开始”不能替代用户的长期目标；“自营是研究主线”也不能变成一定推荐自营的结论。

旧版服务研究提示词保留在 [更新前的 Git 版本](https://github.com/shopable-ai/gpt-thinking/blob/045114049ddbb198bcc1740bf8ae337e3c0a8d68/docs/incubator/knowledge-asset-production/market-research-prompt.md)。当前同一路径已改用新版，不再同时维护两个互相竞争的主提示词。

## 3. 整体商业主链

```text
具体人群与实际问题
        ↓
视频 / Podcast / 访谈 / 课程 / 文章 / 官方资料 / 实践
        ↓
权利与来源检查，恢复真实知识及必要视觉信息
        ↓
围绕读者任务组织：概念、论点、证据、案例、方法、限制
        ↓
知识地图与完整解决一个子问题的免费内容
        ↓
自己的分发渠道、相关读者与持续触达
        ↓
识别看完之后仍值得付费解决的问题
        ↓
匹配的书 / 教学 / 工具 / 服务 / 推荐 / 商业机会
        ↓
真实付款、交付、使用、退款与复购
        ↓
更新知识、产品与渠道，检验能否持续盈利
```

视频只是知识来源和选题线索，不是产品边界。不能用“三个视频 = 三章”代替知识架构，也不能用补写更多文字冒充新增价值。

## 4. 原始假设与必须检验的问题

原始设想：一条或几条视频可能只覆盖主题的一部分；可以先整理其中已有知识，再向需要的人提供更系统的垂直知识产品。

需要分别验证：

- 读者真正缺系统理解，还是时间、实践、反馈、工具或代为执行？
- 现有免费材料、已有书课、AI 搜索与 Notebook 是否已经足够？
- 更完整的结构能否减少理解或执行困难，而不仅是页数更多？
- 能否取得自己的相关受众，而不是只找到有播放量的来源？
- 谁愿意按什么范围付款，交付、审稿、更新和获客成本是否可持续？

不能预设所有视频都知识密度低；公开报价、关注、收藏和有趣的反馈，不等于成交与利润。

## 5. 免费内容与付费产品的连接

建议研究这条关系，而不是故意删掉关键步骤制造付费墙：

```text
免费内容完整兑现一个小承诺
        ↓
读者的下一项真实任务或剩余缺口
        ↓
范围清楚、能独立使用的付费产品
```

| 读者或企业的下一步需求 | 候选交易 | 需要验证的不是 |
|---|---|---|
| 系统理解、查阅、按顺序学习 | 书、电子书、专题指南 | 仅仅文档更长 |
| 学会操作、得到反馈 | 课程、工作坊、付费教学 | 仅仅把书录成视频 |
| 直接使用、节约搭建时间 | 模板、代码、工作流、资料包 | 仅仅下载次数 |
| 希望别人负责完成任务 | 咨询、外包、实施与维护 | 仅仅有人询价 |
| 选择合适工具或现有学习产品 | 软件联盟、书课推荐、授权分销 | 仅仅推荐点击 |
| 持续获得有效更新或专业判断 | 会员、知识库、情报订阅 | 仅仅每月生成很多内容 |
| 品牌希望接触相关受众 | 广告、赞助、合格线索 | 仅仅总阅读量 |
| 企业希望接触匹配人才 | 职位展示、招聘赞助或合规撮合 | 仅仅有招聘栏目 |

读者、使用者、付费者可以不是同一个人。广告主、软件商、招聘企业有独立采购条件，不能把它们的假设收入直接相加。

## 6. 保留的方向性判断（不是市场事实）

免费内容可以高质量、完整且独立有用；收费产品可提供更好的组织、练习、工具、反馈、便利或持续更新，并非只能卖秘密知识。

先明确人群与任务，再决定适合书、教学、模板、服务还是推荐已有产品。不默认 SaaS、全库知识图谱、一本大书或全部变现方式同时启动。

在研究比较后，优先检验一项主收入，再判断一项自然相关的辅助收入。广告、会员与招聘是否加入，由各自买方证据决定。

“取得来源 → 获得自己的读者 → 成交 → 完成使用”是不同环节，必须分别核查。

## 7. 技术只支撑内容保真和首个实验

[technical-baseline.md](technical-baseline.md) 保留历史技术路线：字幕优先、必要时 ASR、Speaker / Timestamp、视觉恢复、统一资料包、语义单元、知识结构与发布。

本轮没有重新安装工具、跑完整视频或复现性能评分。旧文档的评分和“已经能够完成”等表述，只能作为历史候选判断，不能当成已验证事实。

技术增量研究优先看：保留原始来源与引用；区分作者原话、综合解释、个人推断和原创实测；不得用标题或二次摘要补造原视频内容。

## 10. 下一轮如何继续与写回

在 `shopable-ai/gpt-thinking` 当前最新 `main` 上，先完整阅读本总览和 `market-research-prompt.md`，再按需读取技术基线。实际执行研究，不只是改写提示词。

应回答：优先哪类人群与问题、免费内容怎样解决子问题、剩余付费缺口是什么、先卖什么、谁付款、什么证据支持、怎样取得首笔收入与检验成本。

比较至少 8–12 个候选场景，按证据给出首选与两个备选；争取 50 条可复核记录，不能凑数，分别报告独立主体、来源和买方证据数量。提供范围明确的受控样例、价格证据与试验参数、30 天方案和停止条件。

研究实际完成后，优先写回同一主题目录：`research-report.md` 保存本轮研究与建议，`evidence.md` 保存来源、日期、口径和证据边界；需要可计算模型时再增加相应文件。它们目前不是已完成文件，不为占位创建空模板。

同步更新本总览的状态、证据缺口和接续入口。保留思路变化的原因；不把“研究建议”标为“市场已验证”或“已有收入”。

写入前后核对分支与最新提交，保留其他会话变更，不重置、不强推。研究任务不授权联系潜客、购买产品、投放广告、收集简历或对外发布商业内容。

## 11. 后期整理原则

继续在此目录探索即可，不再为“商业模式”“灵感”“视频”“提示词”复制出四份相同正文。

当同一主题确实产生独立业务、稳定知识或执行项目时，再拆分或迁移；留下来源与新位置。孵化状态允许暂停或否决，保留判断依据即可。
